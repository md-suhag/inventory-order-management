## 1. Conventions

| Topic | Convention |
|-------|-----------|
| Naming | snake_case plural tables, snake_case columns; Prisma models PascalCase via `@@map`/`@map` |
| Primary keys | `uuid` (UUIDv7, generated by Prisma). Natural keys for `permissions.key`, `document_sequences.document_type`, composite PK on `role_permissions`, `business_settings.id = 1` |
| Money | `numeric(14,2)`; unit cost / WAC `numeric(14,4)`; percentage rates `numeric(7,4)` (0–100) |
| Quantities | `integer` (base unit) |
| Time | `timestamptz(3)` UTC; `date` for expected delivery |
| Enums | PostgreSQL enum types (`OrderStatus`, `PaymentStatus`, `InventoryMovementType`, …) |
| Soft state | `status` enums (`ACTIVE`/`ARCHIVED`, products also `INACTIVE`); users `is_active` |
| Deletes | `RESTRICT` for anything historical; `CASCADE` only for owned children that have no history of their own (draft lines, images, role grants, tokens) |

## 4. Inventory ledger design

`inventory_movements(product_id, type, quantity_change, previous_stock, resulting_stock, unit_cost, purchase_receipt_id | order_id | sales_return_id, adjustment_reason, notes, idempotency_key, performed_by_id, created_at)`

| Type | Sign | Reference | Written by |
|------|------|-----------|-----------|
| OPENING_STOCK | + | none | product creation with initial stock |
| PURCHASE_RECEIPT | + | purchase_receipt_id | goods receipt |
| SALE | − | order_id | order confirmation |
| SALE_CANCELLATION | + | order_id | cancelling a confirmed order |
| SALE_RETURN | + | sales_return_id | completing a return (resalable lines) |
| ADJUSTMENT_IN / ADJUSTMENT_OUT | + / − | none; `adjustment_reason` required | manual adjustment |

Database guarantees (all tested in Phase 1):
- `resulting_stock = previous_stock + quantity_change`, both ≥ 0, change ≠ 0.
- Sign matches type; exactly the matching reference is set; adjustment reason iff adjustment; `OTHER` needs notes.
- `UNIQUE (order_id, product_id, type)` → one SALE and at most one SALE_CANCELLATION per order line.
- `UNIQUE (purchase_receipt_id, product_id)`, `UNIQUE (sales_return_id, product_id)` → a receipt/return cannot hit stock twice for a product.
- Append-only trigger; `products.stock_quantity >= 0`.

Reconciliation invariant (checked by tests): for every product, `stock_quantity = Σ quantity_change` and equals the latest movement's `resulting_stock`.

## 6. Denormalised data & consistency strategy

| Column | Derived from | Single writer | Guard |
|--------|-------------|---------------|-------|
| `products.stock_quantity` | Σ movements | inventory service | row lock, CHECK ≥ 0, movement arithmetic CHECK |
| `products.cost_price` | WAC over inbound movements | inventory service (+ audited manual edit) | row lock |
| `purchase_items.received_quantity` | Σ receipt items | receiving service | conditional update, CHECK ≤ quantity |
| `purchases.paid_amount`, `refunded_amount`, `payment_status` | payments | payments service | purchase row lock, CHECK refunded ≤ paid |
| `orders.paid_amount`, `refunded_amount`, `payment_status` | payments | payments service | order row lock, CHECK |
| `orders.returned_amount` | Σ completed returns | returns service | order row lock, CHECK ≤ total |
| document `subtotal/discount/tax/total` | lines | pricing function at draft save | total formula CHECK; lines immutable after draft |

Snapshots that are intentionally copied (not redundant): order/purchase line product name, SKU, unit, prices, tax, cost; order billing details.

## 7. Concurrency support in the schema

- Row-level locks on `orders`, `purchases`, `products` (`SELECT … FOR UPDATE`), lock order header → products by id.
- Conditional update on `purchase_items.received_quantity`.
- UNIQUE constraints on idempotency keys and on movement references turn duplicate submissions into constraint violations, never double effects.
- CHECK constraints as backstops for negative stock, over-receiving, over-refunding, over-crediting.
- `document_sequences` row lock serialises number allocation per document type only.
